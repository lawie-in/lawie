# Test and CI gaps

- `apps/web` has a Jest setup (`jest.config.js`, `jest.setup.ts`, `yarn workspace @lawie/web test`) with about 820 tests (14 Oct 2026), covering the consent flow, intake (BriefStep, CourtPicker, OneFlow), the form renderer, Ink cost lines and export utilities. Many pages are still untested, so a green `web` run says nothing about pages outside those areas.
- `packages/shared` has no tests of its own, despite every service depending on it and CI building it first.
- `.github/workflows/ci.yml` runs the sanity tier (T-688, `test:sanity`, whole run 5 minutes or less) on every push, with jobs for `gateway`, `auth`, `drafting` (with a golden-set dry run), `billing`, `email-worker` (`test-email-worker`, which also runs `packages/email-client`'s sanity tests), `web` (`Web build`: typecheck, production build, sanity tests; the lint moved to the full tier) and `test-golden-set` (the `scripts/golden-set/__tests__` harness tests, which no other job ran before T-688). `.github/workflows/full-tests.yml` runs the full tier with coverage, the Codecov uploads and the web lint nightly, on `release/**` and on dispatch; it never blocks a merge. See `.claude/docs/coverage.md`. A real-model golden-set job exists but is not yet a required check (T-376).
- There is no `t607` test file in any workspace. T-607 was a production config fix, so its settings are untested; Arjun's T-688 list named "t607 settings" for drafting sanity, but there is nothing to list.
- `scripts/` is not a yarn workspace, and nothing in CI ran its tests before T-593. `.github/workflows/scripts-tests.yml` now runs `yarn test:scripts` (Jest, `scripts/__tests__`) on pushes to the listed branches (path-filtered) and on every PR to `main`, `develop` and `develop_staging`. Branch protection matches the job's check-run name: require `Run scripts tests` (shown on PRs as `Scripts tests / Run scripts tests`).
- The only deploy workflow, `deploy-production.yml`, is a no-op placeholder — it only triggers on `workflow_dispatch` and runs a single job that echoes a message. There is no staging environment. Deployment is manual today; don't assume merging to `develop_staging`, `develop` or `main` deploys anything.

- Email tests on develop (email-worker, any ticket that sends mail): use only the SES mailbox simulator addresses (success@simulator.amazonses.com, bounce@simulator.amazonses.com, complaint@simulator.amazonses.com), never real addresses. SES is out of the sandbox since 14 Oct, so real addresses would really be mailed (Arjun, 14 Oct 2026).
