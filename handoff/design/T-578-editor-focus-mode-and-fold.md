# T-578 design note: editor above the fold, focus mode (and T-579 Word button)

Rajesh, 23 Oct 2026. For Kunal (T-578) and whichever lead takes T-579. Tokens of record: `DESIGN.md`. No signed string changes wording; two signed lines move position and Ajay confirms the moves (marked AJAY below).

## 1. Why the editor is low today

On `dashboard/documents/[id]` the column above the editor is: header row (back, title, court; save state, Save, PDF, DOCX), the export-error banner when one exists, the starting-draft label (boxed), the T-197 disclaimer (boxed card), the Annexures card (title, help line, 220px primary button; grows on success). At 1280 x 768 that is roughly 330px before the first line of the draft. Three things fix it: unbox the two notes, move Annexures out of the column at desktop, and give the editor a focus mode.

## 2. Normal view, new order (all widths)

1. Header row, as it is.
2. Export-error banner, only when there is an error (unchanged, T-233 focus rules).
3. **Notes row.** One block, no card, no border, no fill: the starting-draft label (when present) and the T-197 disclaimer as two Body Small lines, Muted (`--muted`), 20px line height, 4px apart, `role="note"` kept on each. Byte-for-byte text. The starting-draft label keeps `font-weight: 500`; the disclaimer is 400. Total height 24 to 48px. **AJAY (confirmed 23 Oct):** the disclaimer line moves from a boxed card to a plain line in the same position, byte-identical, visible at the top without scrolling at all three widths, contrast at least 4.5:1 (Muted on Wall is 4.6:1 by day, 5.4:1 at night).
4. **Annexures row** (below 1024 only; see 5 for desktop): one 44px row, Card fill, Control Line border, `rounded-nl-md`: FileText 16px, `Annexures` (Mukta 500, 14px), the help line `Prepared from the details you entered.` Muted 13px after it (hidden below 480px, the help text then goes to `aria-describedby` on the button), and `Create annexures` as a **ghost** button on the right (DESIGN.md One Primary: the page's primary is the draft, so the pack button is not brass-filled any more). The success, missing-details and error states open **below the row** exactly as today, on action only; the row never grows at rest. `role="region"` and the strings stay as they are (AJ T-381 signed).
5. **Desktop (≥ 1024, the existing `lg`)**: the Annexures row moves to the **top of the right rail**, above the filing checklist, as the same one-line row but stacked (title and help line, then the full-width ghost button, 44px). Its states open under it inside the rail. Nothing about annexures remains in the editor column at desktop. **AJAY (confirmed 23 Oct):** the annexure strings do not change, only where the card sits.
6. Editor, starting at: ≤ 200px from the top of the viewport at 1280 (top bar 64 + header 44 + notes ≤ 48 + gaps), ≤ 290px at 768 and 390 (plus the 44px Annexures row).

Acceptance (Playwright, three widths, 768px tall viewport): the editor's content box top edge is at most 220px at 1280 and at most 300px at 768 and 390, with a draft that has a starting-draft label and a disclaimer.

## 3. Focus mode

- **Control:** a toolbar button at the right end of the editor toolbar, after a divider: Maximize2 16px, `aria-label="Full screen"`, `title="Full screen"`, `aria-pressed` toggles. In focus mode the same button shows Minimize2 with `aria-label="Exit full screen"`. One button, two states; no second control anywhere else. 44px hit area (the toolbar buttons are smaller today; give this one `min-h-[44px] min-w-[44px]` and leave the others for the toolbar rebuild).
- **Layer:** not the browser Fullscreen API (iOS Safari has none for elements, and the keyboard rules differ). The editor root becomes `position: fixed; inset: 0; z-index: 45` (above the sidebar at 30 and the page, below every dialog at 50, the consent sheet at 55 and the command bar at 60), on Wall (`--wall`), with the toolbar as the first row and the page (the 210mm sheet) scrolling under it. `body` scroll is locked while open (`overflow: hidden` on `html`, restored on exit). Safe-area insets padded (viewport-fit=cover is on).
- **What stays visible:** toolbar; save state (`Saving… / Saved / Save failed / vN`) moves into the toolbar's right group next to the control while in focus mode, so autosave is never hidden; and a **footer line**: the T-197 disclaimer, Muted 13px, one line, centred, 8px padding, at the bottom of the layer. **AJAY (ruled 23 Oct):** the footer is **sticky**, pinned to the bottom edge of the layer for the whole time focus mode is open, never scrolling away and never dismissed; same text. It is `position: sticky; bottom: 0` inside the layer's scroll container (or a flex child after the scroll area), with Wall fill and a Line hairline above it, so the draft never runs under it.
- **Exit:** the control, or Escape (when the editor has focus, Escape exits focus mode; the Tiptap editor does not use Escape). Focus returns to the control. Export, Save and the Annexures row are not inside the layer: the user exits to reach them (one press). Autosave, versioning and unsaved edits are untouched: the editor instance is the same node, only its container's classes change (do not remount Tiptap).
- **Motion:** 150ms opacity fade of the layer in and out; under reduced motion none. No scale, no slide.
- **Widths:** 390: the sheet fills the width with the 16px gutter, no `max-w-[210mm]` shadow box (the sheet is the layer); the toolbar wraps to at most two rows and the control stays in the first row at the right (`order` it first in DOM after the undo group if needed). 768 and 1280: the sheet is centred at 210mm with 24px top padding.
- **Dialogs:** ExportBlanksDialog and the delete dialog are z-50 and open above the layer; they are not reachable from inside it today, which is fine.
- **Both themes:** the layer uses the same tokens as the page; nothing new.

## 5. T-577: paragraph count with live price

Vikram (23 Oct): cap 25; 1 to 10 paragraphs = 2 Ink, 11 to 18 = 3 Ink, 19 to 25 = 4 Ink; under-delivery settles at the delivered band. Ajay (AJ-577-M1 to M3, 23 Oct): the **minimum is the pack's mandatory paragraph count** (`min`, from the server with the quote; bail_regular 7, or 8 in custody), never 1; the cost shown before Generate is a ceiling. Range is `min..25`. Arjun's count semantics (body paragraphs only, pack defaults, which types ask) are the ticket's points 1, 4 and 6.

- **Where:** on the brief step, one row directly above the Ink cost line and the Generate button, only for document types that ask. Label `Paragraphs` (Mukta 500, 14px), a help line in Muted 13px: `Body paragraphs. Headings, prayer and verification are not counted.` (AJ-577-M1). The minimum is visible before Generate: it is the stepper's floor, the track's left end, and the `−` button goes dim at it.
- **Control:** a stepper, not a free field or a slider: a 44px group with `−` ghost, a numeric input 64px wide (tabular, `inputmode="numeric"`, `aria-valuemin={min}`, `aria-valuemax=25`, `aria-valuenow`, `role="spinbutton"` on the input), `+` ghost; `−` is `aria-disabled` at `min` and `+` at 25 (dimmed, still focusable); Control Line border, `rounded-nl-md`. Arrow keys step by 1, Shift+arrow by 5, Home/End to `min`/25. Typed values clamp on blur to `min..25` and the clamp is announced through the cost line's live region with the same line the server 400 uses: `Choose between {min} and 25 paragraphs.` (AJ-577-M1 string 4, with `{min}` filled). While `min` is not yet known (the quote is loading) the stepper is disabled and the cost line shows its loading state. The default is the pack's default, pre-filled, so a user who never touches it gets today's flow.
- **Band marks:** under the stepper, a 4px track running from `min` to 25 (not from 1), Brass fill up to the current value, Wood for the rest, Control Line ticks at the band edges that fall inside the range (10 and 18; a band wholly below `min` is not drawn); labels `2 Ink`, `3 Ink`, `4 Ink` centred under the segments that exist, Muted 12px tabular. Static, no motion. The current band's label is Text, the others Muted. This is the only place the band table is shown; no tooltip.
- **Price:** the existing `InkCostLine` directly under the stepper re-quotes on each committed change (blur, step press, arrow key), through the single-quote path so shown equals charged (T-388): `Uses 2 Ink` / `Uses 3 Ink` / `Uses 4 Ink`, loading state `Working out the Ink cost...` as today, Generate off while loading. No per-paragraph price is ever shown; only the band's Ink. The line keeps the signed `Uses N Ink` form: it is the ceiling, and the under-delivery line below is where a lower debit is explained. No `up to` wording.
- **Under-delivery:** nothing on the intake. The done event's chip shows the Ink actually used (T-545), and when it is less than quoted the draft-ready folio shows one Muted line under the chip: `This draft has fewer paragraphs than you asked for, so it used {n} Ink.` (AJ-577-M3; {n} from the server; shown only for a real debit, never on a failed or free draft). Never a refund word, never a promise of length.
- **Server refusal (out of range, 400):** the stepper's input gets the Rust error ring and the line `Choose between {min} and 25 paragraphs.` (AJ-577-M1 string 4, `{min}` from the server's response) under it; Generate stays enabled.
- **Widths:** 390: label and help stack above the stepper, the stepper and band track are full width; 768 and 1280: label left, stepper right-aligned in the same row, track under both. Both themes from tokens; reduced motion: nothing moves anyway.
- **Not asked:** fixed-form types (affidavit, vakalatnama) never show the row; the brief is unchanged for them.
